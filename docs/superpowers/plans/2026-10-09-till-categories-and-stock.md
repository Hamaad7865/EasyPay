# Categories and stock from the tablet: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** on the tablet, make, change and remove a category (name and colour), add or remove stock with an
optional reason, and switch an item's stock to counted.

**Architecture:** three new ops in `sync_push` (`category.save`, `category.remove`, `stock.adjust`) and one
more field on `item.save`, in migration 0087. The till asks them online and waits, as it does for
`item.save`, then pulls. Two form readers hold the till's rules and are unit-tested; two sheets draw them,
shared by the restaurant's Menu and the shop's Products & stock.

**Tech stack:** Postgres (plpgsql), Node test scripts, Kotlin, Jetpack Compose, Room (unchanged).

**Spec:** `docs/superpowers/specs/2026-10-09-till-categories-and-stock-design.md`.

**Rules of this folder:** another session commits here. Stage only the files a task names. Before taking
0087, `ls db/migrations | tail -1` must still say 0086. Apply migrations to dev only (`node db/migrate.cjs`).
Never push a tag. Test on `easypay_claude_till` (port 5586), never on the owner's emulator.

**Codes.** Where `sync_push` already has a code for a refusal it is used, so the spec's `unknown-store`,
`unknown-line` are `bad-store`, `bad-variant` here; a gone item is `bad-item`, a quantity not above zero
`bad-qty`. New codes: `has-items`, `bad-reason`, `not-counted`, `pick-variant`, `not-enough-stock`.

### Task 2: migration 0087

**Files:** create `db/migrations/0087_till_categories_stock.sql`, generated by a script in the scratchpad
(`dumpall.cjs` then `gen_0087.cjs`, as 0082 to 0084 were) from dev's live `sync_push` and `push_item_save`.

- [ ] **Step 1: dump** dev's live functions; confirm the dumped `sync_push` has `'not-premium'` in its
  codes (0085 is in it).
- [ ] **Step 2: write the generator.** Its output:
  - `push_category_save(p_tenant, p_emp, p)`: id, name (`left(btrim(..), 60)`), colour (`''` or
    `^#[0-9a-fA-F]{6}$`, else `bad-payload`); `may(p_emp, p, 'items.edit')` else `forbidden`; row
    `for update`: found and deleted `bad-category`; found, `update categories set name, color`; not found,
    insert with `sort_order = (select coalesce(max(sort_order), -1) + 1 from categories where tenant_id =
    p_tenant and deleted_at is null)`. Returns `{category_id, created}`.
  - `push_category_remove`: same right; `has-items` when a live item has it; soft delete; not found and
    not this client's `bad-category`.
  - `push_stock_adjust`: reads `store_id`, `item_id`, `variant_id`, `units` (integer), `direction`,
    `reason`, `note` (`bad-payload` on a cast failure or a direction that is neither); `units <= 0`
    `bad-qty`; reason null `adjust`, else must be in the direction's list or `bad-reason`;
    `may(.., 'stock.adjust')`; store live and this client's or `bad-store`; item live or `bad-item`;
    counted (`track_stock or category.is_stock`) or `not-counted`; variants as 0073 (`pick-variant`,
    `bad-variant`); `v_level := stock_level_for(..)`; out of more than `v_level.qty` `not-enough-stock`;
    `perform stock_move(tenant, store, item, variant, ±units, reason, null, null, null, p_emp, note)`.
    Returns `{item_id, qty}` with the level after.
  - `push_item_save` as it is live, with: `v_track boolean` read from `p->>'track_stock'` (null when
    absent); on update `track_stock = case when v_track is null then track_stock else v_track and not
    v_open end`; on insert `coalesce(v_track, v_shop) and not v_open`.
  - `sync_push` with the five codes added after `'not-premium'` and three `when` lines after
    `item.remove`. Every replacement must match exactly once or nothing is written.
- [ ] **Step 3:** `ls db/migrations | tail -1` says 0086; write 0087; `node db/migrate.cjs`.
- [ ] **Step 4:** the new suite passes; `item-ops`, `premium-gate`, `retail-till`, `push-policy` pass as

### Task 3: the till's form readers, tested first

**Files:** create `android/app/src/main/java/com/restopos/core/data/CategoryForm.kt`,
`.../core/data/StockForm.kt`; tests `android/app/src/test/java/com/restopos/core/data/CategoryFormTest.kt`,
`StockFormTest.kt`.

```kotlin
object CategoryForm {
    // the swatches, and the colours a category with none is painted in, by its place in the list
    val SWATCHES: List<String>            // twelve "#RRGGBB", the first eight CAT_COLORS's
    fun read(name: String, color: String?): Result<Category>   // Category(name, color: String?)
    fun shown(color: String?): List<String>   // SWATCHES, with a valid colour not among them added last
    fun refused(code: String?): String
}
object StockForm {
    enum class Way { In, Out }
    class Reason(val code: String, val label: String)
    fun reasons(way: Way): List<Reason>
    fun units(typed: String): Int?        // "3" -> 3000, "1.5"/"1,5" -> 1500, "0"/""/"1.2345"/"abc" -> null, at most 7 digits before the point
    fun after(now: Long, units: Int, way: Way): Long
    fun refused(code: String?, shop: Boolean, left: String): String
}
```

- [ ] **Step 1: tests.** CategoryForm: a name is trimmed and cut at 60; blank refused "Give it a name"; a
  colour is upper-cased `#RRGGBB`, null and "" are no colour, `red` refused; `shown("#123456")` has 13 with
  it last, `shown(SWATCHES[2])` has 12, `shown("nonsense")` 12; every swatch is distinct and well formed;
  `refused("has-items")` and `refused("unknown-op")` say something of their own. StockForm: the `units`
  table above; `reasons(In)` codes `receive, found`, `reasons(Out)` `damaged, expired, lost, internal,
  supplier_return`; `after`; `refused("not-enough-stock", ..)` names what is left.
- [ ] **Step 2: fail** (`android/gradlew -p android :app:testDebugUnitTest --tests "*CategoryFormTest*"
  --tests "*StockFormTest*"`). **Step 3: implement. Step 4: pass. Step 5: commit.**
